# 03. 요구사항 정의서

> 크롬 확장프로그램 — 군 장병 대상 열차 승차권(좌석) 취소표 자동 신청
> (02-workflow.md에서 정리한 워크플로우를 바탕으로 구체적인 기능/비기능 요구사항을 정의)

## 1. 기능 요구사항 (Functional Requirements)

- 사이드 패널에 "중지" 버튼을 두어, 자동화 실행 중 사용자가 언제든 직접 멈출 수 있어야 한다.
- 진행 상태 표시는 "실행 중" 여부만 보여주면 충분하다(상세 로그, 시도 횟수 등은 불필요).
- 자동화 도중 대상 탭이 다른 페이지로 이동되거나 닫히면, 자동화는 즉시 중단되고 디스코드 웹훅 + 카카오톡 나에게 보내기로 알려야 한다(신청 완료 알림과 동일한 채널).

## 2. 비기능 요구사항 (Non-Functional Requirements)

- 보안: 디스코드 웹훅 URL, 카카오 API 토큰 등 민감한 값은 별도 설정 파일에 넣고, 그 파일을 `.gitignore`로 제외해 GitHub 저장소에는 올라가지 않게 한다.

## 3. 화면/UI 요구사항

- 구체적인 레이아웃/디자인은 사용자가 별도로(Claude Design 등으로) 만들어 전달할 예정 — 본 문서에는 화면에 들어가야 할 요소만 정리한다.
- 사이드 패널에 필요한 요소: 신청 대상 슬롯 2개(각 슬롯: 날짜, 출발역, 도착역, 완료 표시), 시작 버튼, 중지 버튼, "실행 중" 상태 표시.

## 4. 데이터 요구사항

- 사이드 패널 입력값(날짜, 출발역, 도착역, 완료 상태)은 영구 저장하지 않는다 — 확장프로그램을 껐다 켜면(또는 크롬 재시작 시) 매번 새로 입력해야 한다.

- 단, 자동화 실행 중에 사이드 패널을 닫았다가 다시 열면 입력했던 값과 진행 상황(어느 슬롯까지 완료됐는지 등)은 그대로 유지되어야 한다. 즉 "확장 재시작/크롬 재시작" 시에만 초기화되고, "패널을 닫았다 여는 것" 자체로는 초기화되지 않는다.

## 5. 권한 (Chrome Extension Permissions)

지금까지 정해진 기능을 기준으로 필요할 것으로 보이는 권한(구현 단계에서 최종 확정):

- `host_permissions`: `https://www.dtis.mil.kr/*` (콘텐츠 스크립트 주입 대상), 디스코드 웹훅 도메인, 카카오 API 도메인(알림 발송용 fetch 호출).
- `sidePanel`: 사이드 패널 UI.
- `scripting`: confirm/alert 오버라이드 스크립트를 MAIN 월드에 주입하기 위함.
- `tabs`: 대상 탭이 이동/종료되는지 감지하기 위함.
- `power`: 자동화 실행 중 PC 절전 방지.
- `storage`(session): 패널을 닫았다 열어도 입력값/진행상황을 유지하기 위함(브라우저 재시작 시엔 초기화).

## 6. 우선순위 / MVP 범위

- 별도의 단계적 우선순위 없이, 02-workflow.md와 본 문서에서 정한 기능을 모두 1차 버전에 포함한다.

## 7. 미해결 질문 / 제안

- [제안] 패널을 닫아도 값이 유지되려면 상태를 패널(UI) 쪽이 아니라 백그라운드(서비스 워커)나 `chrome.storage.session`처럼 별도 위치에 보관해야 함 — 패널이 열릴 때마다 그 상태를 다시 읽어와 화면에 반영하는 구조로 설계해야 함.
- [제안] 다른 사람(미래의 나 포함)이 저장소를 받아서 쓸 때 어떤 값을 채워야 하는지 알 수 있도록, 실제 값이 없는 예시 설정 파일(예: `config.example.js`)을 함께 만들어 두는 것을 권장.
- [제안] 5번(권한) 목록은 구현 단계에서 실제로 필요한 권한만 다시 확인해 최소화하는 것을 권장(Chrome 확장 스토어에 올릴 계획이 없더라도, 불필요한 권한은 줄이는 게 안전함).
